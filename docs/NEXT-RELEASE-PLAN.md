## 用户明确约束：保留 qpdf 解密真实需求

**不采纳代码评审 P1-1，以及 P0-1/30天清单中将加密权限位用于限制 qpdf 解密的部分。** 保留现有密码打开、空用户口令的权限加密文档处理、去加密并导出可编辑副本；不因本次评审新增默认只读、二次权限确认、审计日志或删除解密入口。既有原件保护、取消不写文件和密码错误处理继续回归。

非加密文档的数字签名识别/保存结果说明另列为文档完整性任务，与 qpdf 解密能力及权限限制分开；不得借此恢复已排除的功能限制。

## 复核结论：可取的架构方向，需纠正的证据推断

| 外部发现 | 本轮判断及调整 |
| --- | --- |
| P0-2 全量重写一律属于 P0 | 普通保存的整文件物化/序列化成本成立，但全量写出不自动等于内容错误。拆成性能/峰值内存优化与输出保真门禁；仅书签保存已经跳过原生内容合成，但仍有 pdf-lib 全量序列化，不能称为完全没有分流 |
| P0-2 建议用 replace-input 做增量写 | 不采纳该技术等同关系：qpdf --replace-input 写临时输出再替换原文件，不是 xref 追加更新。增量写也不自动保持签名有效或原有线性化快读性质 |
| P1-3 OCR 缓存身份与输入不符 | 部分不成立：ocr-jobs.cjs 的作业 id 已哈希实际输入 bytes、OCR选项与引擎版本；S.ocrTask.bytes 是 UI 会话复用标记。实际需检查的是同一会话编辑修订变化后的旧任务挂接、已有Folio层的skipText语义和人工校对保留 |
| P1-3 强制 OCR 一律使用原件 | 不直接采纳，会忽略用户当前修改。统一显式 sourceRevision/inputHash/layerPolicy，明确原件与当前内容的识别语义；改变默认行为前验证既有场景 |
| P1-7 保存没有事务 | 表述过重：已有会话捕获、独立working文档、成功写入后更新handle/baseline以及原子替换路径。需要集中阶段状态与失败注入验证，不以引擎数量证明没有事务 |
| P1-9 renderer可任意传路径读取文件 | 未证明可达：暴露的是 droppedFile(File)，preload调用getPathForFile；普通字符串/JS伪造File不能直接变成磁盘路径。main边界值得加强，但不能直接宣称已存在任意文件读取漏洞 |
| P1-9 drop token和拒绝UNC | token只有在可信来源验证后登记才有意义，不能“把不可信路径换成token”就算修复；不将will-navigate当作文件拖入凭证，不一刀切禁用用户合法网络盘PDF |
| P1-10 全应用单一原生队列 | 每个bridge内部串行，但当前已有字体/背景/流式/qpdf等独立桥及OCR池；看门狗应按桥与命令改造，不把已分离的工作重新描述为一个队列 |
| P2-11 预览文档图上下文不同 | 提升优先级：worker抽单页后再apply，Form判据依赖Catalog中的StructTreeRoot等状态；存在预览/保存能力判断分叉风险，需构造样本复现，不能仅靠保存时签名校验报错兜底 |
| P2-12 stdout污染 | 采纳并提升到可靠性优先项：Python redirect_stdout不能拦截全部原生fd输出。桥中解析失败清空pending而进程继续运行，迟到响应还可能错配后续请求；这是静态推断，需故障注入确认 |
| P1-2 fsType | 推荐过滤与手选写缓存确有不一致；统一能力解析不只判断restricted位，还应按OS/2版本处理禁止子集、仅位图等。不能宣称栅格化就自动满足任何字体许可 |
| P2-13 字体缓存 | 共享临时路径、加载缺少字节/元数据校验值得修；风险要区分Linux多用户与Windows当前用户目录，不把所有平台都称为已可投毒 |
| P2-14 批注缺少AP/P/NM | 当前新增批注字典未显式生成这些字段；显示/打印兼容需专项。不同字段/批注类型的要求不同，不能一概断言所有输出都是非法PDF |
| P1-4/5 抽象和拆分 | 采纳稳定模型、错误码和命令边界；不以app.mjs行数减半、统一HRESULT或减少PDF库数量作为成功指标，也不要求先做全量架构重写 |
| 30/60/90天承诺 | 改为依赖与验收切片，未做原型/估算前不承诺固定工期 |

- 核心界面：空态、书签树（长标题/多选/匹配/拖放）、页面编辑（字体下拉/溢出通知）、OCR校对、规则/拆分/表格/对照、首选项、大文件工作区，以及处理中/失败/取消状态。

| C6 扫描表重建与校对导出 | F09 | 先支持清晰有框线扫描表+人工调栅格，随后再扩无框线/多级表头/跨页；CDLA 版面候选不等于单元格拓扑，须单独验证结构模型或规则。保留单元格源坐标、文本/置信度与校对状态 |
| C7 表格规模和数值列 | F09 补充 | 1,000 格限制分前端模型/检测/导出逐层改为预算，不直接删上限；虚拟网格、分页/分块导出与可取消任务。先验收 40×30（1,200格）和更大稀疏表，再定上限；数值转换可选、逐列预览，默认保留原文 |
| C8 多文件队列 | F12 | 依赖稳定单文档任务和检查点；输出命名/冲突处理、单文件失败隔离、暂停/取消与结果报告，避免一个坏文件阻塞整批 |
| C9 对照报告 | F14 | 像素、文本/字形、区域外变化、未决疑点分别导出；标明引擎/版本/缩放/容差/输入输出哈希，文本相等不能代替字形正确 |

C7 数值列须区分统计值与标识符：前导零、长账号/行业代码、缺失符号、百分数、千分位和小数点必须可复核；保持文本原值，CSV/XLSX 均回归公式样式输入，不能因“数值智能识别”引入自动公式执行。

大文件路径的推荐依赖：C1→C3（配合 B1）→C4/C5；C2 可独立切片推进，**不将连续滚动完成设为目录 OCR 的硬前置**。真正多 GB 文件与稀疏占位文件分开记录，降低“只测偏移却宣称可处理整本”的风险。

## 实测、性能和发布门禁补充

1. 固定回归集与探索集分开：固定集承接 P6 65 页、P7 20 页及 Issue #2/#3 私有复现；探索集覆盖金融、计算机、艺术、数学、法律的原生/扫描/混合 PDF，登记来源、授权、哈希、页号和选样方法。发现问题后做最小复现，避免挑选成功页。
2. 普通操作覆盖短替换、长插入、整段删除、数字/标点、样式、窄表、多次撤销、保存重开；书签覆盖生成、批改、分层拆分、目标校准；OCR 覆盖方向、漏检、跨格、补识别与人工结果保护。未运行项标未运行。
3. OCR 真值分别记录字符错误率、检测遗漏、跨格归属和数值单元格完全匹配；数值前导零、负号、小数点和缺失符号单列。没有人工真值不得输出“准确率”。
4. 大文件在 16/32 GB Windows 机器用真实 0.75/1.5/3/>4 GiB 样本测首屏、跳页/滚动 P50/P95、整棵进程树峰值 RSS、磁盘峰值、OCR吞吐、取消耗时及恢复。冷/热缓存分开；指标阈值由基线确定，不捏造秒数或提速倍数。
5. A1/A2/A3 的受支持用例若出现未解释的内容丢失、区域外改动、字体静默替换或写回与预览不一致，阻断发布；A5 人工校对丢失/重复文字层同样阻断。受限样本保留明确限制，不能靠删除失败测试关闭 Issue。
6. 保留当前源码/portable ZIP、Windows 同提交 EXE 验收、验证记录与 SHA-256 交付方式。程序功能验收和本次文档核查分开记账；本次更新不触发新版能力声明。

## 市场判断的使用方式

- 价格表仅作外部报告的历史快照；正式对外材料需重新核对厂商、区域、税费、永久使用权/维护与大版本差异，本计划不复述未核实价格。
- 论坛、Trustpilot、专利与搜索文章只作痛点线索；无竞品并排实测就不宣称准确率、速度或保真胜出。
- 后续用同一合法样本和相同步骤比较 Folio、PDF-XChange、ABBYY/Acrobat：任务完成时间、人工修改量、输出错误、资源占用、离线条件分别记录，价格独立比较。
- 以真实目标用户的目录生成、数值校对和续编任务验证价值，验证前不以市场评分替代工程验收。
