# Folio PDF Studio 2.8.3 UI 与功能深度审阅及优化方案

> **审阅版本**：Folio PDF Studio `2.8.3`（提交 `99527c9`，Electron `44.11.3`）  
> **审阅时间**：2026-11-20  
> **审阅依据**：对 2.8.3 仓库全部 13 张界面实拍截图（`docs/images/2.8.3/01-reader.png` 至 `13-ocr-review.png`）、前端 HTML/CSS/ESM 源码（`src/`）、主进程与预加载脚本（`main.cjs`、`document-tabs.cjs`、`preload.cjs`）及 2.7.0 历史审阅对照后的实证核验。  
> **边界说明**：本次审阅为静态源码 + 实拍截图交叉审计，未运行外部 AI 付费调用、真实物理打印与第三方底层引擎（LibreOffice / veraPDF / Rust 创意内核）内部源码审计；所有问题均已对照 2.8.3 当前源码逐条核实，排除 2.8.x 已修复事项。

## 一、一页核心结论

### 1.1 当前版本评价与已取得进展

Folio 2.8.3 是一套**功能纵深极强、工程克制且本地优先**的 Windows 桌面 PDF 工作台。相比 2.7.0，2.8.x 系列已经完成了非常扎实的迭代：
- **视觉现代化显著提升**：引入 `modern.css`、`ocr.css`、`bookmarks.css`、`organizer.css`，整体建立起清爽的现代桌面视觉语言，明暗主题与 5 套配色对比度良好。
- **高风险缺陷修复及时**：2.8.3 解决了设置复选框对比度过低、OCR/阅读复选框变形、无效设置提交、未变化设置重复刷新 PDF、搜索栏 Esc 关闭等问题；`flow-ui.mjs` 已通过引用共享 `originalLayout` 消除了逐键全量序列化开销；保存链路支持条件增量写入并保留书签目标精度。
- **核心护城河明确**：书签规则引擎、离线 RapidOCR 校对工作区、内嵌图像/矢量工作室、原字位保留的段落编辑及完整的本地验证体系，是同类开源桌面 PDF 工具中少见的深度能力。

### 1.2 核心短板与结构性瓶颈

当前最大的问题不再是“缺少重型能力”，而是 **“重型专业能力已建成，但高频日常体验（阅读/搜索/批注/标签/欢迎页）仍偏早期原型，且快速叠加导致 UI 细节瑕疵、入口碎片化和 CSS/前端架构债务加速积累”**：

1. **可见 UI 缺陷（P0）**：2.8.3 官方截图中即暴露出 OCR 校对选中项“蓝底黑字”低对比度、小册子打印预览角标缩成 4px 黑点、页面组织器“选择”标签重复、书签 QC 按钮无禁用态且“定位”被遮罩阻挡等立即可修问题。
2. **日常阅读与批注体验断层（P1）**：缺少最近打开文件（MRU）/会话恢复、无深色护眼阅读页面、全文搜索无缓存索引/无结果侧栏/不支持跨行与区分当前命中项、批注仍依赖弹窗逐次画框且不支持划词高亮，连续滚动模式下批注与搜索高亮仅显示在单个激活页。
3. **信息架构过载与入口重复（P1）**：顶部标题栏与 Ribbon 常用区重复摆放保存/撤销/重做，编辑态顶栏高达 4 层；“文档工具”单弹窗塞入 19 项异构功能；旧版“页面操作”与新版“组织页面”、旧版“文档属性”（含 0.x 过时文案）与“属性与元数据”并存。
4. **样式与前端架构债扩大（P1/P2）**：自定义 CSS 从 2.7.0 的 6 个文件膨胀至 **10 个文件、7,442 行（305 KB）、150 处 `!important`**；`i18n.mjs` 靠全局 `MutationObserver` 劫持文本替换；AI 审批仍使用阻塞式 `window.confirm()`；文档转换/合并拆分仍在渲染进程做整文件 Base64 编解码。

## 二、UI 与交互体验审阅（UI / UX Review）

### 2.1 立即可修的具体视觉与交互缺陷（P0，基于 2.8.3 截图与源码实证）

#### 1. OCR 校对列表选中项“蓝底黑字”，几乎不可读
- **现象与证据**：在 `docs/images/2.8.3/13-ocr-review.png` 右侧“校对”列表中，第一条选中项 `96% · FOLIO / PUBLIC DEMO` 显示为深蓝色高亮背景叠加深色文字，对比度严重不足。
- **源码根因**：`src/ocr-ui.mjs:115` 使用了原生 `<select id="ocr-results" size="7">` 实现结果列表；`src/ocr.css:243` 虽然写了 `#ocr-results option:checked { background: var(--accent) ...; color: var(--on-accent); }`，但 Chromium/Electron 对失焦态或自绘 `<select><option>` 的前景色覆写极不稳定，容易回退为 `#ocr-results option` 的 `color: var(--text)`。
- **优化建议**：将 `#ocr-results` 从原生 `<select>` 替换为自定义语义列表（`role="listbox"` + `role="option"`，支持虚拟滚动或分组），不仅彻底消除选中态对比度 Bug，还能承载**置信度彩色胶囊、可疑字高亮、单条快速确认/忽略按钮**和更自然的多行排版。

#### 2. 打印对话框小册子/多页预览中，页码与“空白”字样缩成 4px 墨渍
- **现象与证据**：在 `docs/images/2.8.3/07-print.png` 右侧预览区，空白左页的左上角有一团无法辨认的黑色小点。
- **源码根因**：`src/printing.mjs:370, 396-404` 将叠加层 `<svg data-overlay>` 的 `viewBox` 设为物理 PDF 点（例如 A4 横向为 `841.9 × 595.3`），并直接用 `font-size: 9` 绘制文字 `p.number ?? "空白"`。当预览缩放至 ~360px 宽时，SVG 用户单位按约 `0.43×` 缩放，导致 `9pt` 文字变成约 **3.8px** 的糊点。
- **优化建议**：按 `sheet.width` 动态计算角标字号与内边距（如 `Math.max(18, sheet.width * 0.032)`），或改用 HTML 绝对定位角标覆盖层；对小册子自动补齐的空白页，在居中区域绘制浅色斜纹底与清晰居中的“空白页（小册子补齐）”提示。

#### 3. 页面组织器工具栏出现两个“选择”，语义与视觉歧义
- **现象与证据**：在 `docs/images/2.8.3/04-page-organizer.png` 第二行工具条中，从左到右排列为：`选择 [全部|奇数|偶数|无] [页码，如 1-5, 8] 选择 [插入到选中页之后 v]`。第二个“选择”紧贴下拉框且缺少明显按钮边框，视觉上会被误读为右侧下拉框的标签。
- **源码根因**：`src/page-organizer.mjs:832-836` 中，前面有 `<span>选择</span>`，输入框后又有 `<button data-range-select>选择</button>`，紧接着是无可见标签文本的 `<select data-insert-position>`。
- **优化建议**：将 `data-range-select` 文案改为“选中范围”或改为输入框内嵌确认图标按钮（支持回车直接生效），并在其与插入位置下拉框之间增加竖向分隔线 + 显式标签“插入位置”。

#### 4. 书签质量检查（QC）弹窗：0 选中时操作按钮全亮，且“定位”被弹窗遮挡
- **现象与证据**：在 `docs/images/2.8.3/03-bookmark-review.png` 中，未勾选任何条目时，`尝试修复`（蓝色强调）、`仅删除节点`、`删除节点及子项`、`检测所选网络链接` 全部呈可点击状态；此外，每行右侧的 `定位` 按钮紧跟文字长度浮动，形成参差不齐的锯齿列。
- **源码根因**：
  - `src/bookmark-qc-ui.mjs:9, 19-25` 未根据 `chosen.size` 更新按钮 `disabled` 状态，点击时仅静默 `if (!chosen.size) return;`；`#qc-links` 在未勾选任何 URI 书签时也会触发 `正在检测 0 个链接…`。
  - `src/bookmark-qc-ui.mjs:21` 点击 `定位` 后在底层阅读区执行 `surface.go(n.target.page)`，但**模态对话框及模糊遮罩并未关闭或收起**，用户无法看到跳转结果。
- **优化建议**：
  1. 根据 `chosen.size` 和选中项中的 URI 数量动态禁用对应按钮，并显示已选数量（如 `尝试修复 (3)`）。
  2. 将 `.qc-row` 改为网格/Flex 布局，使 `定位` 按钮统一右对齐，并点击 `定位` 时提供“最小化到侧栏/浮窗定位”或点击即关闭弹窗直达目标页的选项。

#### 5. 字体工作台：样本预设标签无激活态，且不支持文档字体视图
- **现象与证据**：`docs/images/2.8.3/05-font-workbench.png` 中 `中英混排 / English / 标点符号 / 常用汉字` 四个预设按钮视觉完全一致，看不出当前选中的预设；列表底部仍是手动点击的 `加载更多`。
- **源码根因**：`src/font-tools-ui.mjs:12, 58` 从未给预设按钮设置 `aria-pressed` 或高亮类；第 25 行直接拼接 `a.style.fontFamily = '"' + ... + '",system-ui'`（若字体家族名含双引号会破坏 CSS 声明）。
- **优化建议**：补齐预设按钮的 `aria-pressed` 选中胶囊样式；用 `JSON.stringify(family)` 转义字体名；以 `IntersectionObserver` 实现自动触底加载（或虚拟列表）替代手动 `加载更多`；增加来源筛选（全部 / 当前文档字体 / 内置字体 / 系统字体 / 含中文）。

#### 6. 页面文字编辑：悬浮移动手柄遮挡上方正文，且字体框缺少下拉affordance
- **现象与证据**：`docs/images/2.8.3/10-text-editing.png` 中，活动文本框左上方的蓝色移动手柄直接压在上方标题 `A clear starting point` 的首字母 `A` 上；顶部编辑栏里的 `Helvetica` 输入框没有下拉箭头，易被误认为只读文本框。
- **优化建议**：移动手柄改为文本框外侧左侧偏移（或在顶部空间不足时自动翻转至右下/左侧边），且非悬停态降低不透明度；字体选择器补齐下拉箭头与点击展开指示；进入页面编辑模式时，若右侧属性栏处于折叠状态，可提供显眼提示或自动展开 `.page-edit-context` 面板。

#### 7. 创作工作室：双重 Undo/Redo 且标题栏按钮状态可能失步
- **现象与证据**：`docs/images/2.8.3/11-image-workspace.png` 与 `12-vector-workspace.png` 中，窗口标题栏（第一行）和工作室工具栏（第二行）各有一组 `↩ ↪` 撤销/重做按钮，用户难以区分哪个作用于画布、哪个作用于 PDF。
- **源码根因**：`src/window-chrome.mjs:12-15` 在 `studio-active` 时将标题栏撤销/重做代理到 `.studio-history [data-history="edit.undo"]`，但其 `MutationObserver` 只监听 `original`（PDF 按钮）和 `document.body.class`，**并未监听工作室按钮的 `disabled` 属性变化**，导致标题栏按钮启用状态与画布历史脱节。
- **优化建议**：进入创作工作室时隐藏标题栏的 PDF 快速操作区（或将其直接并入工作室历史栏并监听工作室按钮状态），彻底消除视觉重复与状态失步。

### 2.2 信息架构与工具栏拥挤（P1）

#### 1. 顶栏层级过多与按钮重复
- **现状**：
  - 正常阅读态下，标题栏快捷区（`window-chrome.mjs:10`）已有 `保存 / 撤销 / 重做`，而紧挨其下的 Ribbon“常用”页（`index.html:39-55`）又放了一套 `保存 / 撤销 / 重做`。
  - 进入“页面编辑”态（`10-text-editing.png`）后，窗口顶部垂直堆叠 **4 层横条**：① 标题栏+文档标签（40px）→ ② Ribbon 分类栏（30px）→ ③ Ribbon 命令栏（42px）→ ④ 页面编辑栏+排版状态子栏（~80px），合计占去近 **200–220px** 垂直高度，在 1366×768 或 200% DPI 笔记本屏上挤压正文阅读区。
- **优化建议**：
  - 标题栏保留文档标签、AI、搜索、主题/设置与窗口控制，**取消与 Ribbon“常用”页重复的撤销/重做/保存**（或仅在 Ribbon 折叠态 `header.ribbon-collapsed` 时在标题栏显示快捷保存/撤销/重做！）。
  - 进入“页面编辑”模式时，将文字编辑工具栏作为**上下文 Ribbon 页**（类似 Word/Acrobat 的上下文选项卡）直接替换第 3 行命令条，而非在第 3 行之下再叠加第 4、5 行，立即回收 ~80px 纵向阅读空间。

#### 2. “文档工具”成为 19 项异构能力的超级杂物弹窗
- **现状**：`src/document-utilities-ui.mjs:4-24` 将 7 大类、**19 个工具**（文档信息、元数据、Web 线性化、压缩、PDF/A 归档/验证、PDF/X 印刷/预检、图层、标签/阅读顺序、PDF/UA 无障碍验证、AES-256 加密、表单查看/填写/创建、导出图片/Word/Excel/文本）全塞进同一个弹窗。在 `06-word-export.png` 中，用户明明在 Ribbon 点击了“导出 Word”，打开的弹窗标题却写着泛化的“文档工具”，左侧还要拖着长长的滚动列表。
- **优化建议**：
  - 按任务域拆分轻量专用弹窗或独立工作台：例如将“导出中心（Word / Excel / 图片 / 纯文本）”独立成清晰标签页弹窗，“优化与印前（压缩 / Web 优化 / PDF/A / PDF/X）”独立分组，“加密与安全”独立；若保留统一工具箱入口，务必在左侧顶部增加**实时搜索过滤框**，并在从具体 Ribbon 按钮直达时将弹窗标题动态设为对应任务名（如“导出 Word”）并自动滚动选中项入视区。

#### 3. 功能入口重复与过时文案残留
- **现状核实**：
  - **页面工具三重入口**：`ribbon.mjs:29` 的“组织”页同时摆放 `插入空白页`、`组织页面`（`page-organizer.mjs`）、`合并 / 拆分`（`document-assembly-ui.mjs`）和旧版 `页面`（`app.mjs:2168 pagesDialog`）。旧版 `页面` 与新版 `组织页面` 能力高度重叠，且 README 中还需专门解释两者行为不一致。
  - **元数据双入口 + 过时警告**：`app.mjs:2231 metadataDialog()`（更多工具 → 文档属性）与 `document-utilities-ui.mjs` 的“属性与元数据”功能重复；且 `app.mjs:2234` 仍写着过时的 0.x 提示：*“保存采用完整重写……不提供段落自动重排、表单编辑或安全涂黑”*，与 2.8.3 实际能力自相矛盾。
  - **加解密入口分离**：“导出无密码副本”（`decrypt`）藏在“更多工具”，“密码加密”（`encrypt`）藏在“文档工具 → 保护”。
- **优化建议**：淘汰或下沉旧版 `pagesDialog`（将其唯一独有的“导出当前页 PNG”合并到“导出 → 导出图片”或“页面组织器”右键菜单）；合并两个文档属性入口并删除过时文案；将“加密 / 解密 / 权限检查”统一收口至“保护与安全”。

#### 4. 窄窗口命令被直接隐藏且缺少全局命令面板
- **现状**：`src/ribbon.css` 的容器查询与媒体查询在阅读器 `≤820px / ≤620px / ≤430px` 及工作室 `≤850px / ≤650px` 下直接使用 `display: none` 隐藏后退/前进、缩放 ±、显示设置、页面布局、旋转和工作室顶部菜单，**未提供对应的溢出“更多”菜单**，导致窄窗分屏阅读时部分操作彻底不可达。
- **优化建议**：
  - 将被折叠的工具栏按钮自动收纳进“溢出菜单（`…`）”，并在 UI 测试中增加断言“任意宽度（含 800×520）下所有核心命令皆可达”。

### 3.2 批注与审阅工作流重构（P1）

- **现状核实**（`src/app.mjs:2255-2409`、`src/viewer.mjs:673-690`）：
  1. **极高操作摩擦**：点击“批注”会弹出阻塞式模态框选择类型/颜色/透明度/线宽/文本，确定后拖出一个矩形，**松手即自动退出绘制模式**（`stopDraw()`），批注 10 处需要弹窗 10 次。
  2. **不支持划词批注**：无法先选中 PDF 文字再一键高亮、下划线、波浪线、删除线或添加评论，只能手动拖矩形框。
  3. **无法编辑与管理**：已添加的批注不能移动、缩放、改色、修改文字，唯一交互是 `ondblclick` **无确认直接删除**；`note`（便笺）只画一个实心色块靠 `title` 悬停查看；无法读取/编辑 PDF 原有的批注；缺少批注侧栏与批注导出。
  4. **多页渲染断层**：由于 `viewer.mjs:673-690` 仅将 `#mark-layer` ID 挂在当前激活页，连续滚动模式下相邻可见页上的批注会暂时“消失”，直到滚动激活该页才重新出现。
- **优化建议**：
  1. **划词即批注（浮动迷你工具条）**：选中页面文本后，就近弹出轻量气泡栏（高亮 5 选色 / 下划线 / 删除线 / 添加便笺 / 复制 / 建书签 / 问 AI），一步到位。
  2. **常驻连续批注工具栏**：点击“批注”进入批注模式并展开次级样式栏（选择类型、颜色预设、线宽、透明度），支持**连续绘制直到按 Esc 或切回手型/选择模式**。
  3. **多页独立标注层**：为 `PageSurface` 中每个已挂载页面维护独立的 `.mark-layer`，不再依赖全局唯一 `#mark-layer` ID，彻底解决连续滚动模式下批注和搜索高亮闪烁/消失问题。
  4. **完整批注生命周期**：支持单击选中批注→拖动/缩放/侧栏编辑内容与样式/按 Delete 删除（可撤销）；便笺改为图钉图标 + 弹出卡片；在左侧栏新增**批注管理面板**（按页/类型/颜色筛选、定位、一键导出全部高亮与批注为 Markdown 读书笔记）；逐步支持解析并编辑 PDF 已有标准批注。

- **源码核实**（`src/page-organizer.mjs:838-879`）：
  - 点击“应用到当前文档”会**重置整个文档的撤销历史**，但该高风险后果仅写在按钮的 `title` 悬浮提示里（第 878 行），用户极易忽略。
  - “页面设置（缩放/裁剪）”硬编码 `pt` 单位，未跟随用户首选单位（`mm`/`pt`），且裁剪仅靠输入 `0,0,0,0` 四个数字，缺少可视化拖拽裁剪框。
  - “页面标记（页眉/页脚/水印/背景）”勾选后收起 `<details>` 没有任何已启用徽标提示。
- **优化建议**：将“应用到当前文档”纳入可撤销的文档快照栈（或至少在未保存编辑存在时弹出明确提示）；裁剪支持在预览图上可视化拖动四边裁剪线并实时联动数值；当页面标记或替换选项处于启用状态时，在对应折叠按钮上显示小圆点徽标。

#### 2. 消除文档工具与合并拆分的渲染进程 Base64 内存风暴
- **源码核实**：
  - `src/document-utilities-ui.mjs:70`：`Uint8Array.from(atob(r.bytes), c => c.charCodeAt(0))`
  - `src/document-assembly-ui.mjs:4-5, 37, 40`：手工分块 `btoa()` 上传每个待合并文件，再 `atob()` 解码结果 PDF。
  - `src/app.mjs:2192`：提取页面同样 `atob(result.bytes)`。
  - **后果**：处理 150–500 MB 的文档压缩、合并、拆分或 PDF/A 转换时，Python→JSON→IPC→Renderer 的 Base64 往返会制造 **3–4 倍峰值内存**并卡死渲染进程主线程。
- **优化建议**：借鉴 Folio 已经在 `source-store.cjs` 和 `file-store.cjs` 做得非常好的**文件句柄/临时路径引用模式**，让 `document-utilities` 和 `document-assemble` 直接在主进程与 Python 之间通过本地临时文件路径传递输入/输出字节，渲染进程仅收发元信息与进度，保存时由主进程直接流式落盘。

#### 3. 扫描件转 Word / Excel 体验提升
- **源码核实**（`src/document-utilities-ui.mjs:36-60`）：扫描件自动 OCR 硬限最多 10 页，超过即报错；且在循环中串行调用单页 `ocr` 与 `reviewConversion` 时**无进度条、无页码进度提示、不可取消且锁死弹窗关闭按钮**（`busy = true`）。
- **优化建议**：放宽或自动分批处理超过 10 页的扫描文档，复用 `ocr-jobs.cjs` 的多进程池与进度/取消机制，展示清晰的阶段进度（如“第 3/12 页：OCR 识别 → 版面重建 → 写入 DOCX”）。

#### 4. 打印对话框性能优化与体验增强
- **源码核实**（`src/printing.mjs:166-176, 276-300`）：
  - 打开打印对话框时，即便默认模式是“全部页面”（缩略图区 `hidden`），第 276 行仍同步循环 `1..pageCount` 创建全部页的 `<button><canvas></canvas><span>` DOM 节点，千页文档开窗卡顿。
  - 每次调整选项触发 `refresh()` 时，第 167 行逐页 `await pdf.getPage(n)` 读取页面尺寸，在尺寸未缓存完前主打印按钮保持禁用。
- **优化建议**：仅当用户切换到“缩略图选页”时才按需（且虚拟化）构建缩略图网格；复用 `S.info.pages` 中已解析的页面基础尺寸（`viewer.mjs:108` 已有缓存）直接参与 `planPrint`，实现千页文档毫秒级打印预览响应；增加打印方案记忆（记住上次选择的打印机、双面、缩放与清晰度）。

### 3.5 OCR 工作区与大文件工作区（P2）

#### 1. OCR 校对效率与工作流闭环
- **现状核实**（`src/ocr-ui.mjs`、`ocr-jobs.cjs`）：底层调度与内存感知非常成熟，但在大规模校对（例如几百页扫描书）时前端体验仍有提升空间：
  - 缺少**批量校对辅助**：如“按置信度排序”“一键确认 ≥98% 高置信度项”“在 OCR 识别结果内执行全局查找替换（统一修正高频误识字，如 `己/已`、`0/O`）”。
  - 缺少**实时资源与剩余时间展示**：多进程 OCR（单进程预估 1.8 GB 内存）时，用户看不到当前内存占用、处理速度（页/分钟）与预计剩余时间（ETA），且在用户同时编辑其他标签时未自动降速让出 CPU/内存。
  - 缺少**与文字编辑的桥接**：OCR 生成的是隐藏双层文字，建议长期增加“将 OCR 区域转为可编辑文本框/导出纯文本或 Markdown”入口。
- **优化建议**：结合 P0 中的自定义列表重构，补齐 OCR 内查找替换、置信度排序、ETA/内存状态条与“编辑活跃时自动降优先级”；长期支持按需在线/离线下载更多语言模型包（日/韩/德/法等）。

#### 2. 统一后台“任务中心”
- **现状**：`onNativeProgress`、`onSaveProgress`、`onLargeSaveProgress`、`onUpdate` 与 OCR 任务流各自为政，用户收起 OCR 对话框后缺少统一入口查看后台正在跑什么、进度多少、能否一键取消。
- **优化建议**：在状态栏右侧建立轻量的**任务中心胶囊**（点击展开任务列表气泡），统一汇总 OCR、大文件保存、文档转换/导出、AI 批处理与更新下载的进度、ETA、取消和完成通知。

#### 3. 大文件工作区（>768 MiB）体验融合
- **现状核实**（`src/large-workspace.mjs:1-120`）：超过 768 MiB 的 PDF 会进入一个全屏原生 `<dialog class="large-workspace">`，其 UI 非常简陋（原生 `<select size="10">` 书签列表、手动翻页按钮、单张 PNG `<img>` 展示、无连续滚动、无正文搜索、无缩略图、风格未融入 `modern.css`）。
- **优化建议**：为大文件工作区应用统一的现代 UI 样式、虚拟化书签树组件（复用主界面树渲染逻辑），补充滚轮翻页/平滑缩放、后台单页文字检索（按需调用 `large_pdf.py`）和基础缩略图条，缩小其与普通工作区的体验落差。

### 3.6 AI 助手交互、安全隐私与工程可持续性（P1/P2）

#### 1. AI 审批与安全体验升级（P1）
- **源码核实**（`src/ai-ui.mjs:122-142, 184, 248, 345`）：
  - 手动审批目前调用 `confirm("AI · " + S.name + " · " + a.action + "\n" + JSON.stringify(a).slice(0, 2200))`——原始 JSON 难读、超 2200 字符直接截断（用户可能批准了被截断的隐藏操作）、阻塞主线程。
  - 自动审批是全局单一布尔开关，开启后无持续视觉提醒（设置说明里提到的“红盾”已失效），且允许 AI 不切标签直接跨文档写操作。
- **优化建议**：
  1. **结构化审批卡片**：改为应用内非阻塞审批面板/抽屉，清晰呈现**操作类型、目标文档、受影响页码/书签数、修改前后摘要（Diff）**，并可展开完整参数 JSON；提供 `允许本次` / `本会话允许同类操作` / `拒绝`。
  2. **权限分级与硬边界**：区分 `只读查询`、`会话内可撤销编辑`、`落盘/外部文件写入` 三级；破坏性操作（整树替换、批量删除、写磁盘文件）永不允许自动审批豁免。
  3. **AI 操作审计与隐私透明**：在 AI 侧栏顶部增加“本次会话操作日志（支持一键整批撤销）”及“数据外发提示”（明确告知本次将向外部模型发送哪些页文字/截图，支持“仅发送元数据”低暴露模式）；文档文本返回模型时增加不可信数据边界标记，缓解 Prompt Injection。

#### 2. 隐私保护与主进程安全加固
- **草稿隐私**：`src/recovery.mjs` 将完整源 PDF 与编辑快照明文存入本地 IndexedDB（默认 2 GB 配额）。处理敏感合同、财务或医疗文件后可能长期残留在磁盘。建议在偏好设置“保存与文件”中新增：**“关闭文档/已保存后立即清除恢复草稿”**、**“退出应用时清理全部草稿”**以及**“一键清除全部本地缓存与草稿”**，并在隐私说明中明示落盘位置。
- **IPC 通道校验**：`main.cjs:108-112` 目前仅对通用通道做了 `objectPayload`（是否为非数组对象）浅层校验，建议为 `native`、`ocr-job`、`web-pdf`、`creative-studio` 等高频通道补齐白名单 command 与字段类型 Schema 校验；对全仓 90+ 处 `innerHTML` 赋值做一轮审计，能用 `textContent`/DOM API 的直接替换，必须拼 HTML 的统一收口到安全模板或 `DOMPurify`。

#### 3. 工程化与发布运维瘦身
- **现状核实**：仓库当前共有 **39 个 `.github/workflows` 工作流**、**87 个 `scripts/` 脚本**、**372 个 `tests/` 测试文件**，存在明显的按版本复制（如历史多版本发布与验证工作流并存），且 `package.json` 仍保留可能已过时的 `test:v1`/`test:v11` 脚本；安装包尚未做代码签名。
- **优化建议**：
  - 将版本化 CI 工作流收敛为 2–3 个参数化工作流（PR 门禁 / 夜间回归 / Tag 发布），历史工作流移入归档或清理。
  - 统一代码格式化规范（当前存在 Prettier 风格与单行压缩风格混写，如 `window-chrome.mjs`、`font-tools-ui.mjs`、`document-assembly-ui.mjs`），接入 `prettier --check` 与 Python `ruff`。
  - 建立 Playwright 视觉回归基线（`800×520` / `1280×800` / `1500×970` × 明暗主题 × 三语），防止样式层叠改动再次引发回归。
  - 中长期规划 Windows 代码签名与更新清单独立签名（如 Ed25519 公钥内置校验），并在体积允许时探索 LibreOffice / OCR 模型等重型组件的按需下载机制。
