# Folio PDF Studio 0.5.0

本版重点是内容编辑正确性、OCR 批量应用、校对数据保留和长任务内存。保留 0.4 的通用书签层级、目标校准、批量样式、拖拽、去重及可视化选页。

## 修复

- **修改一处后同页字距变化**：原对象编辑改为保留未修改内容流，只替换可可靠定位的绘制操作。PDFium 负责生成新的文字/路径片段，pypdf 负责组合；新增内容与原有文字状态隔离，避免继承字距等状态。
- **新增多个文本重叠**：新增对象使用独立 ID；空对象编号不再匹配其他新增对象，并按次序错开初始位置。
- **多页 OCR 应用失败却看不到原因**：应用前检查字体覆盖，增加 DejaVu Sans 回退字体；缺字显示页码、字符及条目。可以校对后重试，或明确选择“排除缺字条目并应用”。不会默认丢掉有问题的文字。零宽空格 U+200B 和 BOM U+FEFF 写入前移除。
- **快速翻页串页**：异步页结果先放入局部变量，通过请求版本校验后再提交给校对界面。
- **校对草稿丢失**：切换条目、翻页、应用、关闭前自动捕获并保存文字、坐标和排除状态；原始识别文字仍保留供核对。
- **大 OCR 结果清空撤销**：书签历史共享不可变 OCR 数据，不再把整本文字重复序列化到每一步中；不同结果版本设独立的估算内存预算，至少保留最近一步。
- **字体句柄累积**：片段生成后显式释放 PDFium 字体句柄；字体覆盖集合只构建一次，避免逐字符重复合并；重复字体/CMap 流在输出 PDF 内复用，减少批量应用的内存和文件体积。

## OCR 工作流程

- 显示实际工作进程、目标进程、每进程线程、活动页、资源限制原因、失败页及近期吞吐。近期吞吐排除缓存跳过和模型冷启动，不代表承诺速度。
- 自动/高性能模式综合处理器与可用内存计算并行度；内存压力下退让，资源恢复后逐步增加。自动模式最多 8 个工作进程，自定义最多 16 个，同时受线程与内存预算约束。
- 页状态可筛选已识别、低置信度、失败和跳过；选择条目时只更新选中框，避免重建整页覆盖层。
- 结果仍按页校对，文本框只编辑一条。全部 OCR 数据不会累加为一个可见文本框；应用时主界面仍持有整份结构化结果，便于书签生成和撤销。
- 后台准备只读结果快照，通过文件引用交给原生写入进程；界面显示写入页进度，支持取消应用。识别结果与源文件保持可重试，应用成功后仍需保存 PDF。
- “收起并继续”保留后台识别；同一文档重新打开 OCR 可继续查看。“关闭”停止未完成识别并保留已完成页。按相同文档、模型和设置重新开始可续做磁盘缓存。
- 简体中文、繁体中文、英文偏好用于校对提示；可保留其他识别文字。输出可明确选择保留原始、统一简体、统一繁体，偏好在本机记忆。转换不改变原始置信度，也不扩展模型可识别的语言。
- 恢复快照分开保存原 PDF、OCR 结果和较小的编辑状态。同一份大数据不随每次书签修改重复写入 IndexedDB。

## 简单文本框

“编辑内容”的文字属性新增宽度、高度与行高设置。宽度大于 0 时按 PDFium 字形宽度自动折行；超出高度明确报错。当前按字符换行，英文单词可能被拆开。

这是新建/替换简单文本框的基础排版，不是 Acrobat 式任意 PDF 段落重构，也没有引入 Story。复杂共用文字组、嵌套、裁剪和无法可靠映射的原对象只读；新增文本仍可用。替换文字使用随包字体，不保证与原字形完全相同。

## 仍需后续版本处理

- 文本与扫描图混合页的“已有文字”完整度判断；目前少量已有文字仍可能触发整页跳过，可取消“跳过已有文字”或指定局部区域识别。
- 局部区域的鼠标框选；当前支持百分比输入，页面范围已有预设和缩略图选择。
- OCR 缓存的可视化清理、配额和自动过期；应用结果引用文件暂随任务缓存保留。
- 真正的多语言模型选择与语言识别分数、方向/栏序的精细校对。
- Story 段落重排、复杂原对象编辑、GPU OCR。

## 兼容性与验证边界

桌面目标仍为 Windows 11 x64；运行包自带 Electron、Python、离线模型和字体。请完整解压后运行 Folio.exe。保存仍使用原件保护与临时写入后替换。

单文件上限仍为 768 MB。PDF 打开、重写和最终预览仍需要完整文档内存；共享撤销和逐页校对并不意味着全流程恒定内存。历史小状态预算 32 MiB，OCR 历史版本估算预算 256 MiB，至少保留最近一步；单个超大结果本身可能超过此值。

实际回归结果见 `VALIDATION-0.5.md`。Linux 的原生/浏览器回归与 Windows 包静态检查，不能替代真实 Windows 启动、文件占用覆盖、混合 DPI 和显卡验收。
