# 2026 年 10 月代码评审采纳与实现记录

审阅输入为用户提供的《Folio 全面代码与体验评审》，固定基线 `da49537d7aeeb99057e3f3283240ff850c57e33b`，对应应用 1.7.1。本次以 1.7.2 的实际变更、反例和测试为交付范围。评审总体方向成立：先保证编辑、应用、预览和最终文件一致，再优化交互和资源。没有把静态风险写成已经发生的事故，也没有因为安全审查删除用户需要的解密功能。

## 比单项修补更好的设计

1. **提交前证明。** 来源身份、会话修订、目标对象和候选参数一起进入提交条件；错误和取消都使旧结果失效。最先在导出与表格中落实，后续推广到图像、目录、字体替换。
2. **原稿、候选与冷重开三方对照。** 只比较预览和输出会让两者共同偏离原文；只提取文字又会漏掉视觉裁剪。本版使用源路径/像素、真实片段、序列化重开交叉验证。
3. **分别衡量目录精度和覆盖率。** 链接、条目提取、OCR、目标匹配各有证据与硬性复核门槛；后续用保留样本标定自动选中精度，并报告人工复核条数和时间。不可用任意百分比分饰未知。
4. **分配前预算和可恢复失败。** 原压缩大小无法估算解码峰值；先检查尺寸再分配。画布上限是局部像素预算，后续需要 renderer、native RSS、缓存和历史统一观测。
5. **按共同状态边界拆分，而不是按文件行数拆分。** 导出、预览事务、来源租约、命令入口是合理模块边界；大规模重写须由测试和测量支撑。

## 验证记录和解释

本地 Linux 执行 quick（188 个 Node 用例，187 通过，1 个仅 Windows 启动器测试明确跳过；6 个 Python 归档/发布测试通过），native 新增 5 组、P7 11 组、P8 5 组，以及真实浏览器回归。浏览器测试通过原生 Python 桥，不把 mock 渲染当成原生验收；表格测试只注入目标失败和请求延迟。智能目录浏览器 7 组通过。

Windows 发行工作流是最终门禁。发行脚本读取新增和既有报告，验证实际 EXE、asar、源码包及 BUILD-INFO，完成后才公开 release；具体运行 URL 和最终 SHA 自动写入 validation 附件和 Release。本文不把“已写好测试”当成 Windows 已通过，最终结果以该附件为准。

官方依据：[Adobe PDF Reference 1.6，裁剪语义](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.6.pdf)、[W3C Tree View 键盘、活动项与选择](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)。原裁剪只能与新路径求交，插入 q/Q 不能扩大既有裁剪；因此超出应明确拒绝或另行设计作用域变换。活动焦点与多选集合是不同状态，需要分别维护。
