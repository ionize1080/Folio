# Folio PDF Studio V1.0 综合开发计划（修订版）

更新：2026-09-15。本轮已进入开发并形成 1.0 RC1：关键书签/字体缺陷修复、用户新增操作与全界面回归已实施；最新状态见第 18 节。

状态：已完成本轮 RC1 实现与自动化验证，Windows 真机验收仍待完成，不标为正式稳定版。旧章节中的“待开发”保留为需求基线；实际完成度及剩余工作以第 18 节和 RC1 验证记录为准。

定位：**书签定位准确、结构可修正、编辑可预测、结果可核查的本地 PDF 编辑器。**

## 依据与范围

本计划核对了《Folio-PDF-Studio-0.9-todo.md》第 4 版、《Folio-PDF-Studio-0.9-validation.md》，并纳入《Folio-PDF-Studio-0.9-bookmark-calibration-diagnosis.md》及用户新增的留白默认单位需求。书签校准、相关文字提取和单位入口已检查 0.9.0 源码并用用户年鉴复现；其余模块以已有交付记录为基线，未重新审计全部源码。未确认的历史能力须先核实，不据此断言尚未实现。

0.9 已实施焦点与工具栏修复、字体选择与继承、扩展方向预选、重叠保留、简单有线表格行高联动、字符样式吸取及编辑草稿恢复。记录中 50 项核心测试通过，已执行真实 PDF 引擎与 Chromium UI 回归；Windows EXE、原生输入法、真实系统缩放、强退恢复尚待实机验收。

这些已有能力进入回归范围，不重复作为 V1.0 新功能立项。已有 OCR、书签、高清渲染、保存与撤销也遵守同一原则。

## 1. CAL-01：书签目标校准修复

### 已确认问题

0.9.0 原码在《巍山年鉴_2025_152.pdf》、留白 5 pt 条件下，精确复现“十八届人大三次会议”书签 X=56.6929、Y=565.7149；真正标题候选对应 X=219.7513、Y=398.4814。默认目标向上偏约 59 mm。

原因是三项叠加：

1. 栏间距约 16–20 pt 小于现有至少 24 pt 的拆分阈值，三栏文字被拼成同一行。
2. 正文“十八届人大三次会议决定（草案）”也包含完整书签名，当前首次子串匹配优先选中了正文提及。
3. 跨行拼接只追加文字，没有追加后续 segments 及其字符索引；命中后续行时退回第一行坐标。

在 15 个可直接建立完整【标题】锚点的书签中，已复现 4 项默认位置偏移；另外 12 个书签不在这项简单检查覆盖内。诊断已完成，不代表软件已经修好。

### 开发待办

- [ ] 跨行候选同步追加片段、start/end、坐标、来源及方向；规范化后的命中范围能追溯到原片段。真正跨行标题锚定标题起始片段，而非拼接窗口起点。
- [ ] 找不到可靠坐标映射时标记不确定，不把首行坐标冒充精确命中；默认保留原目标，用户可明确选择候选。
- [ ] 分栏后再组织行和跨行候选，支持两栏/三栏和局部跨栏标题；避免只按固定间距或页面中点判断。
- [ ] 区分独立标题、【】等明确标题边界、字体/字号/颜色线索及正文包含关系；综合评分，标题证据优先，不能只凭颜色或括号单一规则决定。
- [ ] 阅读顺序尊重栏结构；父书签上下文和邻近关系作为辅助。同页多处同名标题证据相近时标记需复核。
- [ ] 根据实际命中范围去重，同一标题的单行/多行窗口不显示成多个不同位置；保留真正不同位置的同名候选。
- [ ] 通用同行片段关联与多栏阅读保持可配置，修复年鉴校准不能破坏原有同行匹配；不依据文件名、行业代码位数或特定列名增加硬编码分支。
- [ ] 预览同时高亮命中文字、所在标题区域与最终跳转点，简述推荐依据；候选直接显示物理页、位置和匹配类型，避免必须阅读大段拼接文字。
- [ ] 大幅移动及多候选显示行内提示；支持逐项跳过、手选候选和整批撤销。参数变化导致重算时保留仍有效的用户选择，过期结果不能应用。
- [ ] 校准仍使用几何与标题证据作为基础，普通文本 PDF 无须等待 AI；本问题不以升级 OCR 模型替代修复。

验收：修正年鉴已确认的 4 项偏移；覆盖后续第 2/3 行命中、真正跨行标题、正文同名提及、同名多标题、两/三栏、旋转与裁切页面、宽松规范化映射、行业代码同行匹配，以及校准后保存重开。

## 2. UNIT-01：留白默认单位首选项

### 用户操作规则

在已有“偏好设置”中增加“单位与留白”设置组，提供 **默认留白单位：毫米（mm） / 点（pt）**。设置跨文档、跨重启保留；全新安装建议默认 mm。已有用户默认设置如果存在则保留；迁移时不改变已有文档、规则和预设的实际距离。

| 场景 | 预期行为 |
|---|---|
| 首选项设为 pt，新建一次留白操作 | 默认显示 pt，不再每次手动选择 |
| 当前操作从 pt 临时切到 mm | 仅本次使用 mm，全局首选项仍是 pt |
| 关闭后新开一次操作 | 再次从首选项 pt 初始化 |
| 多个操作窗口或规则面板同时存在 | 各自保留本次选择；新窗口读取全局首选项 |
| 修改首选项时已有未完成操作 | 不打断输入、不强改当前窗口；后续新操作采用新首选项 |
| 明确恢复上次未完成草稿 | 恢复其原数值与本次单位，避免改写未完成工作；新建操作仍按首选项 |
| 导入含单位的旧规则/预设 | 保持其实际距离，以当前操作单位换算展示，不把旧数值直接解释成新单位 |
| 切换单位 | 自动换算数值，保持同一实际留白和同一预览位置 |

此次先增加单位首选项，不额外增加全局默认留白大小。各工具的原有默认距离保留其物理含义，再换算为首选显示单位；需要改变大小时直接编辑数值。

### 覆盖入口与 UI

- [ ] 按标题校准书签目标的“标题上方留白”。
- [ ] 自动书签及多级规则生成中的“顶部留白”，并同步转换当前规则列表的所有留白值。
- [ ] 存量书签“调整跳转留白”及相关批量偏移入口。
- [ ] 留白快捷按钮随当前单位显示、按该单位生成清楚的步进值，不再点击后强制切回 mm；原版 +3/+5/+10/-3 mm 固定按钮需要一起调整。
- [ ] 预览、变化摘要和结果列表显示明确单位，必要时在详情显示对应原生 pt 坐标。
- [ ] 单位下拉放在留白输入框旁，沿用紧凑布局，不增加常驻工具栏；修改单位自动刷新预览，不弹出反复确认。

范围明确为“留白单位”，不是把所有数字都统一成 mm：字号、原生 PDF Left/Top 坐标及明确标注 pt 的专业参数继续按其原有含义显示。若将来扩展为通用长度显示单位，应另行设计，而非隐式改变现有字段。

### 数值与兼容规则

- 采用统一换算：1 mm = 72 / 25.4 pt。内部保留完整精度的距离；单位切换只改变表示，不改变实际值。
- 例如 5 mm 切到 pt 应显示约 14.1732 pt；切回仍是 5 mm，不能变成 5 pt，也不能因来回切换累计漂移。
- 格式化显示可四舍五入，但不能把显示后的数值反复写回作为下次换算源；输入步长随单位调整，不影响未改动的精度。
- 规则/预设存储包含显式单位或归一化距离及版本。旧格式按该入口原有格式规则解释，不能套用当前首选项猜测旧数值。
- 负值、零、小数、空值的原有语义分别保留；单位设置不是一次文档编辑，不使无改动文档变成“未保存”。
- mm/pt 转换与旋转页面的留白方向换算分别执行，避免重复乘单位系数或反转方向。

验收：首选项持久化；新建/临时切换/重开行为；各入口与快捷按钮一致；5 mm ↔ 14.173228… pt 往返后目标位置不变；负值与零；旧预设和草稿恢复；更改设置不重写现有书签；规则输入不中断。

## 3. TEXT-01：段落重组与阅读顺序

本项与 CAL-01 共享必要的字符几何、栏界及位置映射，但书签定位和编辑段落采用各自的分组与评分规则；不能简单复用同一套整行拼接结果。

近期公报案例讨论指向文字重组问题：微小基线差及严格坐标排序可能使中文、数字被拆开或串行。已有局部归一化实验有改善，但不代表正式版本已修复，也不能把单个样本的参数直接推广到所有 PDF。

实施范围：

- 按字号、文字方向与局部基线建立自适应行聚类，处理中文、数字、标点的轻微位置差。
- 行到段落综合使用栏界、缩进、行距、字体、标点及列表结构；标题、表格、图片形成分隔约束。
- 将原生字符位置、版面模型结果及用户修正组合使用；模型框不直接等同于可编辑段落。
- 提供“自动 / 保守拆分 / 倾向整段”的重组偏好，仅影响选定区域或页面；高级几何参数留在诊断中。
- 重分析只提出结构变化，保留正在编辑的内容及已锁定结果；不在每次输入时重跑模型。

验收同时考察误拆与误合并。以用户公报、年鉴、政策报告中的标注页验证，不能仅以“框数量更少”判断改善；跨栏串接、文字丢失、重复文字列为重点失败条件。

技术依据：PDF 提取顺序可能不同于自然阅读顺序，见 [PyMuPDF 文本提取文档](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)。版面检测与包含阅读顺序的文档解析是不同层次，参见 [PaddleX 版面检测](https://paddlepaddle.github.io/PaddleX/3.4/en/module_usage/tutorials/ocr_modules/layout_detection.html)及 [PP-StructureV3](https://paddlepaddle.github.io/PaddleX/3.7/en/pipeline_usage/tutorials/ocr_pipelines/PP-StructureV3.html)。上述实现路线是本项目设计建议，不是这些工具对编辑保真的保证。

## 4. STRUCT-01：结构纠错与持久化

- 多选相邻文本块合并；在指定行或光标位置拆段；操作前显示结果。
- 修正区域类型、所属栏与阅读顺序；锁定图片、表格及文本边界。
- 合并默认保留内部字符样式，不自动统一字体。
- 区分“合并为一个段落”和“连接为同一文章的多个文本框”；文本链允许多个段落。
- 支持完整撤销与恢复。纠错结果写入已有工程/草稿机制；先核实其持久化边界，再选择扩展方式。
- 重新打开工作状态、重新运行 AI 后仍尊重锁定；源文件变化导致定位失效时提示重关联，不能静默套用。
- 默认以简洁的区域边框和浮动操作呈现，仅在主动查看结构时显示阅读顺序。

接受标准：误识别后能直接修正；局部纠错不重排整页；用户修正不会被后台推理覆盖。

## 5. DIFF-01：全页变化对照与保存检查

0.9 已有本段前后切换，本版扩展为全页变化地图、并排或叠加对照，点击变化跳转到对象。显示实际受影响的文字、图片、边框和移动区域，而非只有文本框边界。

输出检查分层实施：

- 编辑中以轻量检查维持流畅；不在按键路径上运行整页像素比较。
- 保存后用实际输出重新解析、渲染受影响页，检查文字完整性、缺字/替代、图片颜色及范围外异常变化。
- 以字体替换、表格联动等真实风险选择检查范围；对长文档避免每次全书重渲染。
- 已接受的重叠或有意移动纳入预期变化；几何重叠仍由用户决定，不能重新成为硬拦截。
- 输出失效或写入失败明确报错，保留草稿；变化检查失败与文件写入失败分别报告。

差异图只能辅助审阅，不能把所有抗锯齿差异判成错误，也不能宣称已证明任意 PDF 全部保真。重复保存和共享字体/图片资源的影响应进入回归样本。

## 6. FLOW-01：可控流式编辑

## 7. TABLE-01：简单表格结构编辑

### 12.1 ENTRY-01：识别完成后没有可见编辑框

现状与证据：

- 第 14 页原生 inspect 成功，识别到 589 个文字对象，均被现有检查标为可流式编辑，并检测到 1 个表格。无 AI 时得到 23 个候选；AI 返回后得到 30 个候选。至少在此次引擎复现中，不能归因于“页面完全没有可编辑文字”。
- 当前 `flow-ui.mjs` 的 start 只进入页面编辑模式并建立候选，活动文本框初始隐藏；需要点击候选文字触发 activate 才显示当前段落编辑框。应区分“尚未点击段落”与“已点击但激活失败”。
- 异步入口在分析前记录 page，返回后只检查文件字节是否变化，没有同等的当前页/请求代次检查；切页与分析完成并发时存在旧页会话挂载风险。这是静态代码风险，尚未证明就是用户当时的具体操作路径。
- 后台 AI 更新会重建候选按钮；检查点击过程与候选替换的竞争，以及页壳挂载、背景准备、排版失败后是否有可靠恢复。
- 本轮尝试浏览器 UI 验证，但环境没有可启动的 Chromium 可执行文件，未完成该项动态复现；更不能写成 Windows 真机问题已定位或修复。

开发要求：

- [ ] 明确“正在分析 → 可点击区域就绪 → 正在打开段落 → 正在编辑 / 失败可重试”的状态；成功时提示可编辑段落/单元格数量，零结果要给出原因和下一步。
- [ ] 识别后显示可辨认的候选区域反馈；点击文字后在原页出现编辑边框和光标，不新增跳出式正文编辑器。
- [ ] 分析请求绑定文档身份、页面和请求代次；过期结果不得挂到当前页。切页、关闭和连续点击有明确取消/继续规则，不静默吞操作。
- [ ] 点击过程中稳定候选身份，AI 更新不得使用户按下到释放之间的目标消失；已选段落在后台分析后保持稳定。
- [ ] 挂载和激活失败保留可重试入口，清理失效 session/opening/busy 状态；背景准备和排版异常不能留下“看似编辑模式、实际无操作入口”的状态。
- [ ] 保留简洁本地诊断，能区分原生检查、区域生成、UI 挂载和段落激活失败；耗时与内部信息放详情。

验收：第 14 页首次/重复进入，候选就绪后点击正文与表格；分析期间切页/关闭/连续点击；后台 AI 返回时点击；缩放/滚动后候选挂载；原生异常和零候选恢复。需 Windows 实机与实际中文输入法测试，不以调用引擎成功代替 UI 验收。

### 12.2 TEXT-01 新增：AI 框边缘把标点拆成独立块

本轮实测第 14 页，候选总数从 23 增至 30，表格单元格均为 12 个；新增碎块包括 6 个 `· ` 项目符号和 1 个 `「` 引号。第 2 页也从 12 增至 13，出现独立项目符号。

开发要求：

- [ ] 区域归属结合文字实际重叠、同一行、相邻字符及局部空白，不将模型框中心点测试当作不可跨越的硬边界。

### 12.3 FONT-01：原字体存在但被整段替代

第 2 页第一条正文在附件中使用嵌入的 Type1 子集 `NotoSerifCJKsc-Regular`。原版检查返回非空 fontKey、空的 fontFallback 提示，看起来像可复用；但 `fitz.Font(...).valid_codepoints()` 在该字体上返回空集合，程序将其直接当成真实覆盖信息缓存。

原版 Story 对每个字符查询覆盖集合，结果全部判为不覆盖。对未修改的第一条正文模型执行排版，即精确复现截图的 **138 个字符、116 个非空白字符被替代**：中文主要换成 Noto Sans SC，拉丁文字/数字换成 DejaVu Sans。界面继续显示原请求字体名 NotoSerifCJKsc-Regular，实际绘制字体已发生变化。

这不是已证明原字体缺少这些原有字符；是当前 Unicode 到字形映射/覆盖检测路径未正确处理这一类嵌入字体。不能通过只改显示名或把 coverage 填成所有码点来修复，否则可能产生错误字形。

开发要求：

- [ ] 针对 Type1 及相关嵌入子集，正确核对 PDF Encoding、ToUnicode、字形名称/字形索引和可排版字体映射；覆盖信息不完整与真正缺字分别表达。
- [ ] 空 coverage 不能以“原字体可编辑”状态放行；建立可验证的原字形复用或可靠字体重建路径，映射不足时给出明确局限及替代选择。
- [ ] 不修改文字、只进入编辑并重排时，已有文字不得无提示地整段变字体；原生显示与编辑预览、输出检查共同验证。
- [ ] 真正新增缺字时只回退必要字符，优先同字族/相近风格的可靠来源；不要把中文衬线文本统一自动改成无衬线。
- [ ] 同名字体的不同子集分别保留资源身份，不能仅按字体名称合并或把另一子集的 coverage 直接套用。
- [ ] 工具栏/详情区分“请求字体、实际字体、混合/替代”；大比例回退要在编辑预览中明显可见，用户可选择替代或取消本次编辑。
- [ ] 字号、基线、字距、行距和混合格式同时核对；仅修正字形外观不能掩盖换行位置改变。

验收：原样激活、插入原字体已有字符、插入真实缺字、局部换字体、混合子集及重复保存；实际输出字形与位置、回退数量及所显示字体一致。138/116 是缺陷复现基线，不作为正确结果验收。

### 13.2 已确认的偏移与容差计算

样本：《20_WD_2025002892_国民经济行业分类-original.pdf》，物理第 12 页。使用 0.9.0 自带 PDF.js 与文字提取/生成逻辑复现，基线单位为 pt。

|---|---:|---:|---:|---:|---|
| 017 与中药材种植 | 262.01 | 264.77 | 2.76 | 0.3067 | 分到不同行，匹配只得到 017 0170 |
| 019 与其他农作物种植业 | 162.05 | 164.81 | 2.76 | 0.3067 | 分到不同行，匹配只得到 019 0190 |
| 018 与草种植及收获 | 224.81 | 224.81 | 0 | 0 | 原版正常 |

原版采用 `max(2 pt, 字高 × 0.25)`，9 pt 时容差 2.25 pt，不足以容纳 2.76 pt；改为 0.4 倍时容差 3.6 pt，可恢复该行关联。0.9 倍则放宽到 8.1 pt，本例并不需要这么大。

### 13.3 跨文档比较及证据边界

本次在诊断脚本中使用原版片段提取和合行判断，对三份 PDF 全部 284 页比较 0.25、0.4、0.6、0.9 四档比例，以及通用局部自适应原型。固定比例保留原版 2 pt 最小容差，其余条件一致。下表统计“视觉行聚合组数”，不是识别准确率。

| 样本 | 页数 | 0.25 倍 | 0.4 倍 | 0.6 倍 | 0.9 倍 | 自适应原型 |
|---|---:|---:|---:|---:|---:|---:|
| 行业分类 | 258 | 10,020 | 9,166 | 9,164 | 9,164 | 9,655 |
| QDII 报告 | 17 | 720 | 720 | 720 | 615 | 720 |
| 巍山年鉴 | 9 | 436 | 431 | 431 | 431 | 435 |

0.4/0.6/0.9 与自适应原型都恢复了 017、019 的名称同行关系。QDII 在 0.9 下多聚合出 105 个较大基线跨度组；抽查第 1、4 页发现，确有“左侧单行垂直居中，右侧为两行文字”的同一表格行，不能把这 105 组直接统计为误合并。

本次几何扫描未检出符合“横向明显重叠且基线差超过 0.6 倍字高”条件的冲突组，但这只是筛查指标，不能证明没有跨行错误。没有逐条标注 284 页的真实行归属，因此不能据组数较少宣称更准确，也不能由这三份文档确定最佳全局比例。

补充受控几何反例：两个明确独立的 9 pt 文字行，基线间距为 7.5 pt（0.833 倍字高），单用 0.9 比例会误判同行；若片段来自隔着表格横线的不同单元格，单看基线也会误合并。这些是构造的边界测试，不是假称在用户样本中发现的错误。

结论：可以自动估计容差；0.9 可以作为宽松候选搜索距离进行后续实验，但不宜作为“低于此值一律同行”的判定条件。0.4 在当前样本上修复已知缺字，同样尚不能直接定为通用最优默认值。

### 13.4 拟采用的通用判断流程

1. **局部分析。** 先按文字方向、局部区域和近似字号寻找可信片段；估计局部主文字尺度、稳定基线及真实邻行间距，避免全页一个阈值。优先使用已有文字几何；不强制每次调用版面 AI。
2. **学习偏移范围。** 从同一区域横向相邻、无明显竞争行的高置信度片段中，统计归一化基线差，以稳健分位数或中位数/离差估计正常抖动，并留少量余量。先取保守种子，剔除跨栏/表格边界，再估计，避免用待判定的可疑配对自我证明。
3. **设置邻行上限。** 容差受局部真实行距限制，避免跨过相邻文字行。可实验的形式为 `T = min(局部偏移估计＋余量, 邻行间距 × 安全系数)`；系数通过标注样本和反例验证，不把本次试验数值写成业务规则。证据不足时保守回退，并提示模糊关系。
4. **多条件决定归属。** 综合基线距离、垂直重叠、横向位置、方向、字高兼容性、表格分隔线和竞争行。横向投影重叠且上下错开的普通文本通常不应合行；上/下标、小字号注记单独关联。旋转文字先变换到局部文字轴，不能直接比较屏幕 Y。
5. **选择最佳候选。** 使用稳定的行基线代表值和候选评分，替代“最近四组内第一组满足即加入”；防止 A 接近 B、B 接近 C 就把三条不同基线串成一行。结合空间索引限制候选数，避免全页两两比较。
6. **保留层次。** 文字片段 → 文字行 → 单元格/布局块 → 表格行。两个片段可以同属表格行但不在同一文字行；多行单元格保留内部换行和来源坐标，再按用户选择决定如何组合标题。
7. **规则独立。** 完整行、匹配部分和捕获组模板仍由用户决定。默认不因遇到数字就删去其中一项，也不因出现长句就自动删掉。若用户只需要某些内容，可用通用区域/列选择或正则模板；预览展示实际输入、匹配结果和来源位置。

诊断原型已实现的范围：局部 80 pt 高窗口、近似字号组、横向相邻片段的偏移分布、邻行距离限制、行基线中位数及明显重叠排除；未加入文件名或文字内容分支。原型恢复了 017/019，且没有在 QDII 中出现上述 105 个大跨度聚合组。但这不代表它优于全部固定比例：它仍可能漏关联居中单元格等情形，表格行归属、上下标、旋转和完整标注验收尚待实施。

### 14.3 范围记忆规则

1. 同一文档记住上次有效选择，关闭对话框和重启应用后可恢复；界面显示“已恢复上次范围”，用户随时重新选择。
2. 首次处理新文档默认当前页，并明确显示“当前页”；提供一键全部页，不再隐藏地默认当前页起十页。其他文档不套用旧文件的绝对页码。
3. 按稳定文档身份保存，兼顾同一文档保存后的延续，避免同名文件串用；文件内容或页数变更时验证原范围，越界给出清楚的修正提示，不静默扩大扫描页集。
4. 草稿恢复完成前暂停自动持久化，恢复后一次同步输入框、快捷选项、缩略图和页数摘要；范围状态独立于规则渲染，避免初始化覆盖。

### 16.3 两种校对节奏，共用一个工作区

| 方式 | 使用场景 | 操作 |

| 疑点优先 | 长文档先集中处理值得复核的条目 | 筛选待复核，上一/下一疑点跨页定位；可标记已核对或暂缓 |

沿用已有低置信度和字形/语言提示，增加可解释的待复核状态。低置信度不是一定错误，高置信度也不是已经正确；疑点清零只表示已处理被提示项，不意味着全篇校对完成。未识别出来的遗漏不会自动出现在疑点队列，因此保留全文通读入口。

新增“已核对”独立状态，不修改引擎原始置信度；否则原本低置信度但人工确认正确的条目仍会反复跳回。修改文字、坐标或重新识别后，受影响条目需要重新核对。暂缓项保留单独计数与返回入口，不静默当作已完成。默认疑点队列按页码和阅读顺序导航，避免后台新增结果导致当前位置不断重排。

保留“下一处”按钮，提供“确认并下一处”的快速操作。快捷键需与现有快捷键审计后分配；中文输入法组词期间不得把 Enter/方向键当成提交或跳转。没有疑点时明确提示“已处理当前可用疑点”，不要默认无提示循环回首条。

### 16.4 正在编辑、后台识别与保存

正在校对文字时锁定条目 ID 及所属页面。左侧滚动可以继续，但右侧不自动换成新页条目；显示“正在编辑第 X 页”，提供回到该条和跟随当前页入口。主动选另一条时，先保存当前草稿；保存失败则保留草稿并提示，不以失焦、滚出可视区或虚拟节点回收作为丢弃理由。

识别按页完成后即可查看，不必等整份结束。结果乱序到达时更新对应页，不自动跳到最新完成页；未完成页保留尺寸占位和“识别中”状态，失败与跳过页明确区分，重试不覆盖已校对版本而无提示。后台更新不得抢焦点、改变光标或用旧结果覆盖人工修改。

校对草稿自动保存只表示保存工作状态，不等于已经写入 PDF。应用按钮明确实际页集与条数；隐藏、筛选、滚动或仅标记已检查，不应隐式排除未显示条目或扩大写入范围。关闭后恢复同一文档/任务的页面、选中条目、页内相对位置、筛选和模式；页面或结果版本变化时验证锚点，不直接复用失效列表序号。

### 16.5 性能、状态与验收

连续模式按需渲染可视页及少量相邻页；远处页面释放画布和识别框 DOM，保留页面占位、校对模型与稳定 ID。缓存按像素内存预算限制，不仅按页数；缩放、旋转、窗口变化和快速滚动可取消过时渲染。异步结果绑定文档、任务、页码和修订版本。

状态至少区分“识别完成”“人工检查完成”“校对草稿已保存”“已应用 PDF”，分别计数；仅滚过一页不能自动算已检查。整页确认必须是用户显式操作，支持撤回确认。重新识别只失效受影响区域的校对确认，并保留可恢复的旧修改。

验收场景：

1. 多页连续滚动无需逐页点击，单页模式仍可用；窄窗口、不同 DPI、长页和不同页尺寸不跳动。
2. 点击原图/结果及跨页疑点定位准确，滚动同步不循环、不回弹；缩放后坐标仍正确。
3. 连续滚动、切页、关闭、快速跳转和中文输入法并用时，不丢文字、不串页保存、不抢焦点。
4. 后台逐页完成、乱序返回、失败、停止、恢复时，当前校对位置和人工修改保持稳定。
5. 确认、暂缓、过滤、应用范围、保存重开及校对断点行为可解释；检查进度不冒充识别准确率。
6. 使用数百页扫描件验证缓存有界及滚动响应，记录普通 Windows 电脑上的实际内存、首屏与定位耗时；不能把只含原生文字的长 PDF 当成完整 OCR 压力验收。

本项列入 V1.0 P1 必做，安排阶段 B；本次仅补充计划和静态源码核查，没有修改软件或发布安装包。

## 17. BOOKMARK-SPLIT-01：正则拆分书签与独立层级生成

### 17.1 核心语义与范围

支持把所选一条或多条现有书签，按用户正则生成多条同级书签，或生成多层父子书签。它处理的是原书签标题，不是重新扫描 PDF 正文；不依赖行业、编号格式、固定分隔符或领域预设。

**每条规则、每一层都独立读取本次操作开始时的原始书签标题快照。** 规则二不读取规则一的输出，子级不读取父级的新标题；改变某层的标题模板，不改变其他层匹配所用的输入。批量时每个来源书签单独求值，新生成节点不在同次操作中再次作为来源递归拆分。

### 17.2 两种模式

**同级拆分：** 默认提供“按正则分隔”，也支持“按正则提取所有匹配”及多条独立提取规则。结果成为原父节点下的一组连续兄弟节点，保持用户选择的输出顺序。分隔模式不把分隔正则中的捕获组意外当成新书签；全匹配提取模式则明确选择匹配全文或捕获组模板。

示例（仅说明通用能力，不作为固定规则）：原题 `政策背景；主要措施；实施安排`，分隔正则 `[；;]`，生成“政策背景”“主要措施”“实施安排”三条同级书签。默认去除片段首尾空白、忽略空片段；这些转换在预览中明确展示。

**父子层级：** 默认每层一个规则、一条输出，形成由浅至深的链；每层均有自己的正则、标志和标题模板。高级模式允许多条规则指向同一个父规则形成兄弟分支，不能仅靠修改缩进猜测父节点。

示例原题：`第一章 总则 / 第一节 适用范围 / 一、适用对象`。

| 层级 | 独立正则 | 标题模板 | 输出 |
|---|---|---|---|
| 第 1 层 | `^\s*([^/]+?)\s*/` | `$1` | 第一章 总则 |
| 第 2 层 | `^[^/]+/\s*([^/]+?)\s*/` | `$1` | 第一节 适用范围 |
| 第 3 层 | `^(?:[^/]+/){2}\s*(.+?)\s*$` | `$1` | 一、适用对象 |

以上三条正则分别在同一个完整原题上执行，形成三级父子链。示例已通过独立 Node 正则断言，且验证第二条规则不能从第一层输出提取结果，以防开发时误实现为串行替换；这不是完整软件验收。

### 17.3 规则、未命中与多匹配

- 每条规则包含：启用、规则名称、正则表达式、大小写/多行等受支持标志、匹配方式（首次/全部）、标题模板、父规则或输出层级；样式默认继承，可按规则覆盖。`$0`/`$1`/`$2` 与已有生成器约定一致，未知捕获组给出诊断，不静默输出错误文本。
- 正则及模板改变后，短暂防抖自动刷新当前样本预览，保留输入焦点和展开状态；大批量先验证代表样本，再生成完整变更预览。
- 默认某个必需层未命中时，该原书签不执行替换，保留原项并报告哪条规则未命中。可显式选择跳过未命中层并将后续有效节点提升至最近有效父级，但不能默认静默提升或创建空白节点。
- 同级模式的全部匹配按原题匹配位置排列；多规则模式默认按规则顺序、规则内按匹配顺序。排序策略在预览中可见，不依赖异步完成顺序。
- 层级模式中，一条子规则若输出多项而父规则只生成一个节点，这些子项可同属该父节点。父规则输出多个节点时，必须指定通用关联方式（如匹配序号配对或用户指定的捕获键）；数量不匹配、关联键不唯一则诊断阻止该来源应用，不默认复制到所有父节点形成笛卡尔积。
- 默认不跨不同原书签合并同名新父项，以免页码、跳转目标或原结构被错误合并。未来如增加合并，应单独显式启用并核对目标一致性。

### 17.4 原节点、子节点与跳转目标

提供“替换原书签”和“保留原书签并插入生成结果”两种应用方式。无原有子节点时可默认预览替换，直到用户应用才改动；生成的根节点位于原节点所在位置或明确指定的相邻位置，其他未选书签顺序不变。

原书签已有子节点时，不静默删除、复制或猜测归属；应用前必须在预览里明确选择保留原节点作为容器，或将原有子树整体迁移至指定生成节点。迁移保持原子树顺序和目标。若没有确定策略，该来源暂不应用。批量包含祖先和后代时显示重叠范围并要求消除歧义，不能把同一子树处理两次。

所有新节点默认继承原书签的完整跳转语义：本地目标的页码、视图模式、坐标、缩放及 null 值均保持，不因标题变化自动寻找另一位置。原始命名目标或特殊动作须沿用已有可安全序列化机制，不能悄悄降为第 1 页目标；不支持的动作明确阻止该项转换。

继承目标不表示各个新标题已经被分别定位。如有需要，用户可在拆分后显式调用 CAL-01 校准新节点，单独核对目标变化。新节点具有独立 ID，不共享可变对象；颜色、粗斜体和展开状态默认继承并允许规则覆盖。

### 17.5 交互与提交安全

入口放在书签右键菜单和“整理”中，名称为“正则拆分…”。对话框包含模式选择、规则列表与树形变化预览，固定显示原始标题；每条输出可展开查看输入、匹配位置、捕获组和继承的目标。

预览突出新增、替换、保留和迁移的节点，并显示“选中 N 条 → 新增 M 条，未命中 K 条，存在冲突 J 条”。支持只看问题项；保留原项模式明确提示是否会出现重复标题，不能偷偷去重。规则可保存、导入、导出，复用已有正则模板基础设施，但规则类型和版本必须可区分。

提交绑定来源书签 ID、原题及树结构版本、规则版本和选择范围；用户修改来源或选择后旧预览失效。完整变更先验证后一次提交，单次撤销恢复原书签、所有子树、目标和样式；取消对话框不更改书签。批量存在问题时，默认不应用，用户可明确选择仅应用有效来源，并看到实际应用清单。

正则运行放入可终止任务，设置超时与输出节点上限。处理零宽匹配、全局匹配状态重置、Unicode 字符、空白输出和过长标题；超限或异常不留下半棵树。大批量预览使用虚拟列表并允许取消。

### 17.6 验收与排期

列为 V1.0 P1 必做，安排阶段 C。验收包括同级分隔/全部提取、三层各自读取原题、修改父级模板不影响子级、每层不同正则、未命中层、重复文本、多匹配关联、原有子树迁移、祖孙同时选中、批量不同父节点、特殊跳转目标、保存重开、撤销/重做及恶意耗时正则。

本次只完成需求和计划整合、示例正则验证，尚未实现或发布此功能；与 GEN-01 的通用布局分析、CAL-01 的定位校准保持独立。
