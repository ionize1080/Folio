# Folio 2.8.3 界面排查与实测

2026-11-16，Windows，Electron 44.11.3，200% 显示缩放。以下为发布前本地实测；测试使用独立配置和文档副本。正式完整包由 GitHub Actions 重新构建并验收。

## 已修复

| 问题 | 原因及结果 |
| --- | --- |
| 设置“点了却没选中” | 原来的通用焦点样式覆盖复选框底色。实际状态已经选中，但白色勾号显示在近白背景上。现在聚焦、鼠标点击、文字点击、空格切换均保留清晰的选中状态。 |
| OCR 复选框缩成细线 | 属性栏将复选框宽度设为自动；自绘复选框取消勾选后没有内容，宽度坍缩。现在选中和未选中均保持 16 × 16 px。 |
| 阅读显示设置中的长条复选框 | 状态栏的输入框最小高度误作用于复选框。现在恢复正方形，并放大标签文字，整行可点击。 |
| 小窗口中设置难用 | 调整偏好面板宽度、标签关联及分类图标；800 × 520 下 OCR 使用左右布局，规则编辑区采用整体滚动，避免正文被上下分割成极窄区域。 |
| 数值无效也能应用 | 必填、范围、整数检查先于设置写入；无效字段定位并提示。提交期间防止重复应用。 |
| 设置未改变仍刷新 PDF | 根据实际变动决定 PDF 刷新、书签树重建及属性预览刷新；未变化的磁盘缓存、图形及代理配置不重复写入。 |
| 搜索栏 Esc 无效 | 搜索栏现在可用 Esc 关闭、清除结果，并将焦点返回搜索入口。 |
| 关闭或改色后旧定位线仍显示 | 应用定位线设置时单独更新覆盖层，无需刷新 PDF。回归检查关闭、开启及改色立即生效。 |

原有 10 个设置复选框的勾号/背景对比度约 1.02:1；修复后，测试的 12 种主题与配色组合最低为 5.63:1。此次回归同时检查实际状态和最终可见样式，避免仅验证内部 checked 值而漏掉视觉错误。

## 覆盖范围

- 真实 Windows 操作：偏好设置、配色、复选框和文字点击、书签行高下拉、应用保存、系统文件选择窗口、阅读显示设置、OCR 面板及滚动。主要故障在修改前真实复现，并在安装版本中复核。
- 偏好设置：7 个分类、10 个复选框、8 个下拉的全部 23 个非审批选项；浅色/深色与 6 种配色组合；输入边界、应用、重开、取消恢复、颜色选择器 Esc、刷新后持久化。
- 主界面：25 类入口，在浅色和深色下检查，加上 8 个紧凑窗口状态，共 58 个界面状态；11 种批处理模式、19 个文档工具分区；144 次复选框点击，检查两种状态下的正方形尺寸。最终报告没有界面越界、水平溢出或页面脚本异常。
- 阅读：全部 9 个缩放和 5 个布局选项通过可见菜单选取；书签筛选开关、清空、全文搜索、Esc 和 800 × 520 下的显示设置。
- 图像与矢量：对象选择、原生菜单、三种语言、字体、平移、缩放、画布尺寸、透明背景；图片右键、快速调整、裁剪面板及结束编辑。
- 文档流程：段落编辑 → 文字选区 → 设置应用 → 10,002 个书签 → 增量保存 → 新进程重新打开。分别用 4 页测试文档和 183 页、4,420,960 字节的实际 PDF 副本验证。
- 349 项已有单元测试全部通过。

以上不是所有功能的无限组合穷举。未向外部 AI 服务发送内容，未执行付费调用、实际打印或真实文档上的批量破坏性操作；这些入口检查了可见界面和可逆选项，不代表其所有后端服务都完成验收。

## 性能实测

同机单次测量，包含 UI 自动操作等待；时间会受到文件缓存、字体预热和系统负载影响，不宜当作跨机器性能承诺。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 设置无变化时应用：PDF 刷新次数 | 1 | 0 |
| 同一动作端到端时间 | 334 ms | 293 ms |
| 设置重复打开的暖态中位时间 | 98 ms | 96 ms |
| 10,000 个书签同步构建 | 26.6 ms | 23.5 ms |
| 10,000 个书签实际挂载行数 | 25 | 25 |
| 24 次工具栏分类切换导致的 PDF 区域尺寸变化/DOM 变动 | 0 / 0 | 0 / 0 |
| 60 帧滚动中的主线程长任务 | 0 | 0 |

4 页文件首次打开本轮为 1.20 秒，基线为 0.63 秒；启动和文件打开存在波动，此次不宣称整体启动加速。183 页实际文件打开至文字层就绪约 1.14 秒；三个缩放动作约 107–174 ms，滚动、缩放和工具栏切换阶段没有超过 50 ms 的主线程长任务。

183 页文件第 4 页的选区绘制约 0.4–0.9 ms；普通滚动没有重新测量选区范围。完整编辑测试中，打开编辑模式约 2.05 秒、激活段落约 1.45 秒、应用段落约 1.54 秒、保存约 1.60 秒。该保存同时包含压力测试新增的一万余书签，保存后新进程验证文字和选区正常。

连续开关设置 20 次并执行垃圾回收后，事件监听数保持 280，DOM 节点没有持续增加。小文档 JavaScript 堆净变化约 +30 KB，实际文档约 −24 KB；这支持本次循环中没有明显的设置面板保留问题，不代表所有工作负载的长期内存保证。首次设置打开和编辑初始化仍记录到约 70–121 ms 的阶段性长任务。
