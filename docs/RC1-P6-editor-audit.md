# RC1-P6 编辑修复与验收

基线：RC1-P5，提交 `5af7eedfef348f72e1ceaa362902e68f0a88682a`。本轮依据 10 份公开文档、50 个抽样页和原始中文文档的编辑长测修复。公开语料地址、内容 SHA-256、页码和类型记录在 `tests/public-corpus-p6.json`；文件从发布者网站获取，不放入源码包。

## 默认交互

碰撞、文本框溢出、页外内容显示非阻断状态提示。输入、选择、撤销和保存继续可用；详情由用户展开，工具栏不因通知出现而增高。超出纸张的文字在编辑区域可见，页外提示明确说明导出页面会裁切。退出编辑后，文档状态栏保留提示入口。原内容归属无法验证或字位映射不完整仍禁止错误写回，并保留草稿。

单元格默认保持边界，普通输入走快速排版。格式面板可明确选择扩展方向；推断或不可靠的网格不自动改动边框。

## 原因与修复

| 基线问题 | 原因 | P6 改动与检查 |
|---|---|---|
| F01 命名 ToUnicode 导致整页失败 | NameObject 被当成字节流 | 区分命名/流 CMap；支持命名 Identity 的码点及 CIDToGID；字体异常隔离到单个字体 |
| F02 财务表格多列串行化 | 检测矩形未经列结构校验就当成单元格；单个 PDF 文本对象横跨多个单元格 | 多基线、多列间隙检验；跨格对象保留完整原始行及归属，不按中心点截断；不可靠网格显示提示 |
| F03 框内字位大幅漂移 | 浏览器将部分小字号字体 advance 取整，框外像素检查未覆盖此问题 | 用字体原始分数 advance；回归同时检查原始字位、保存后文字及框外/未编辑页像素 |
| F04 局部修改触发全段重排 | 字数改变就丢弃原始锚点，继承粗斜体被误当成新样式 | 同槽更正保留原字位；能放入原行的插入/删除只重排该行；原生继承样式校验 |
| F05 代码/标题碎片与错序 | 直接按含浮点误差的基线排序；字体片段被当成独立栏 | 先聚合同基线，再横向排序；代码硬换行、粗体标题边界；完整行判栏 |
| F06 表格增长失败信息不清 | 推断边界、字位不完整与溢出被混在同一状态 | 默认保持边界；显式增长；内容完整性与几何提示分开 |
| F07 字体推荐重复计算 | 按整段的前 16 字做小容量缓存；先描边再查覆盖 | 按字形缓存轮廓和掩码，32,768 项上限；先覆盖/嵌入权限过滤；覆盖位图有界缓存 |
| F08 推荐结果过期 | 异步请求只检查模型标识 | 同时核对版本、文本和字体；过期响应不覆盖当前推荐 |
| F09 完成编辑复制整本 PDF | 全量 apply、重新解析、重绘 | 按修改页生成预览，共享原 PDF；保存时按不可变编辑版本合成整本；回滚/撤销共享所有权测试 |
| F10 表格每次输入走原生慢路径 | 所有 cell 被排除出快速路径 | 默认固定单元格使用快速路径；显式扩展才使用原生布局 |
| F11 AI 到达改变点击范围 | 异步识别替换当前候选集合 | 本次编辑的命中区域稳定，AI 只提供布局建议 |
| F12 MingLiU 浏览器拒绝 | glyf 保留位及 sfnt 搜索参数不规范；失败反复重载 | 有边界检查的 glyf 标志修复、目录重建；确定性无效字体负缓存 |
| F13 大文件递归失败 | 全文根对象克隆超出 Python 默认深度 | 保留完整根对象并使用有界克隆预算；预览由 QPDF 复制单页；5 份整本文件写出检查 |
| F14 缺 name 表 | 有效 PDF 字体缺少浏览器必需元数据，或 OS/2、cvt 等表长度为零 | 生成稳定名称及 OS/2；移除空的可选 hint 表；不改变 glyf/hmtx；在实际 Chromium 加载全部解析字体 |
| F15 Type1/CFF 页解析中断 | PDF 允许无 Type1 尾段；无子程序字体省略 Subrs；CFF 默认 charset 省略 | 按 Length1/2/3 验证后补 Type1 解析尾段；允许空子程序集合并保留真实粗斜体标识；恢复默认 CFF charset；隔离字体异常 |
| F16 小单元格无法编辑 | 硬编码 14 pt 入口和 10 pt 验证阈值 | 按真实小单元格建模；布局最小 1 pt，保留字符可读性提示 |
| F17 允许溢出仍被阻断 | 原始字位分支未尊重 allowOverflow | frameOverset 与阻断状态分开；各布局路径一致 |
| F18 光标/预览被裁掉 | 输入层和父页面裁剪，通知改变工具栏高度 | 编辑页允许显示页外内容；扩展 SVG/画布及命中范围；详情浮层；光标不受推断框裁剪 |
| F19 ASCII 连字符导出变成其他 Unicode | 多个码点共享 GID，导出反查产生歧义；结构化提取遗漏独立零宽重音 | 快速、原始锚点和精排加入 ActualText；严格显示列表映射保留零宽重音，只有各候选字体均证明同 GID 时才接受别名；显式单字 ActualText 避免保留宽字位时被 PDFium 或分组器补入空格；原始逻辑空格显式写回，避免相邻字符 ActualText 抑制正常词间空格；MuPDF、PDFium 双引擎核对 |
| F20 raw CID CFF 不可编辑 | 只接受 OTTO 外壳，误将 CID 当 GID | 使用 charset 还原 CID→GID，保留 CFF hint/FDArray/Subrs 封装 OpenType；预定义 Adobe 集合映射；导出前将 CID charset 规范为 GID 顺序，保留轮廓与子程序；双引擎实际墨迹验证 |
| F21 非零 CropBox 无法编辑 | MediaBox 与可视裁剪区原点混用 | 统一为 CropBox 左上坐标，写回保留原页框和旋转；四方向字位回归 |
| F22 图形计数差导致全页只读 | 渲染器合并 path 后对象数不一致 | 验证非 path 顺序及解码文本，只开放对应关系已验证的文字；未知对象不删除 |
| F23 原始连字重复绘制 | PDFium 把 fi/fl 等连字拆为同位置的逻辑字符，逐字符画出导致叠印 | 仅在字体覆盖和同位置/同样式证据完整时合并绘制原连字，逻辑选区偏移不合并；普通不同位置字符不合并；两条原生导出路径精确像素验证 |

| F24 工程重开报页码类型错误 | 新几何通知的布尔 page 字段与工程递归数值校验冲突 | 使用 pageClipped/frameOverset 明确几何含义；非阻断提示完整往返工程文件，真正的非法页码仍拒绝 |

跨引擎检查曾发现 SDK 保存后的 ActualText 正确但实际 CID 字形错误，因此文字提取检查不能代替渲染验证。此次新增非 identity raw CFF/OTTO 墨迹比对，并复测 SDK 五页显示及保存后再次编辑。

## 发布门禁与边界

本地 127 项 JavaScript 单元测试通过，P6 原生 13 项回归覆盖字体元数据、四种旋转的 CropBox、ActualText、完整溢出预览、组合字符、深层对象及真实字体推荐。45 个实际本机字体的对照中，首字符变化后推荐从 P5 的约 701 ms 降至 P6 的 388 ms；同请求命中缓存，冷启动仍约 0.9 秒。这是该机器的测量，不代表上千字体的性能保证。

另外对 372 页中英文年报、492 页规范、2696 页 SDK 和 194 页 RFC 完整原件执行新增文本框写回，全部保持原页数并通过语法和文本检查。此项用于检查完整文件合成，不冒充全书逐页编辑长测。逐页操作、保真指标和剩余限制详见随测试更新的报告。65 页保存后原生对象文字全部保留；58 页仍为完整单段，GNU/RFC/论文/Unicode 的 7 页目标被拆成多个编辑块，后续需保存并核验自有内容层的段落归属和逻辑边界。

`folio-editor-p6.yml` 在 Windows 运行单元、原生、界面、旧版本功能回归、50 页公开语料检查、打包一致性及真实 Folio.exe 验收。发布工作流只采用指定成功任务的同一提交、同一 EXE/app.asar 哈希的产物，附验证 JSON 和 SHA-256。

PDF 不包含可靠的段落语义，无法保证任意扩写仍保持所有原字位。等宽/同槽更正及能在原行容纳的局部编辑优先保持；放不下时需重排。Type3、不能验证的编码/阅读顺序、复杂字符的合成粗斜体以及非 1 UserUnit 仍有限制，保留原对象并显示原因。几何警告不等于内容完整性通过，发布不取消签名、字符映射或字体覆盖检查。
