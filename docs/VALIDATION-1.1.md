# 1.1.0 RC1 验证与边界

## 已验证

- JavaScript 核心回归：77 项通过，0 失败，包含新增规则持久化与正则树筛选。
- 字体证据：刻意修改字体名称的子集仍按实际轮廓匹配回对应完整字体，并覆盖新增缺字。
- 三行逐字符定位样本：等宽替换后未修改字符原点、基线保持；字号变更切换到段落重排。
- qpdf：AES-256 正确密码解密、错误密码拒绝、无打开密码的权限限制移除；源文件字节不变，页数、文档标题及页面模式保留。
- XLSX：合并范围、前导零、中文及公式样式文字值通过重新打开校验。
- OCR：重新打开输出后再次识别，已标记的 Folio OCR 层只保留一次。
- P2 原生回归：中英混排两端对齐、跨框续排、裁剪保护、字体完整性及不可见 OCR 图层通过。
- 两份用户提供的真实 PDF：编辑后保存并重新解析成功；未编辑页面、页眉和页脚区域保持像素一致。原件不随交付包分发。
- Chromium 自动化：规则草稿恢复、筛选后仅修改匹配项、无效正则、解密导出、原字位编辑、字形推荐、无改动退出、表格导出，以及 900/1440px 操作按钮可见性。
- Windows 便携包静态校验：PE 架构及版本、完整 Electron 资源、Python、qpdf DLL、模型、字体、app.asar 与源文件哈希对照。报告随包附带。

## 实际验证范围

业务逻辑、本地引擎和界面测试在 Linux 环境运行；Windows 包只完成静态依赖和资源校验，**未进行 Windows 真机启动、输入法、打印或显卡兼容性验收**。因此交付版本为 RC1，不能把上述测试视为 Windows 实机全功能通过。

## 已知边界

- 保留字位算法用于能可靠映射的水平文字。复杂连字、双向/组合脚本、无法提取的原字体、跨页接续等情形会使用段落重排或保留只读保护。
- 局部行重排优先保证原始行与未修改后缀；复杂改写、缩放或结构变化可能导致整段换行变化。界面显示实际使用的排版方式。
- 字体识别基于可提取的字形证据与本机候选，不能凭少量子集保证找回世界上任意字体。低置信候选应在原页和替代详情中检查。
- 本机字体第一次比较需要扫描候选；后续使用进程内缓存。更换机器或字体安装状态后，可能得到不同的相近候选。已保存 PDF 含实际输出片段。
- 旧版或第三方 OCR 未带本版本的图层标记，不自动删除其隐藏文字。
- 表格导出适用于已识别且可以安全编辑的矩形有线表格；CSV 不承载合并单元格语义，优先用 XLSX。
- decrypt 是通过有效密码打开并重写加密状态，不是口令破解。数字签名在重写后需要重新签署。
- AI/HTML/Markdown 等计划中的探索项不作为本次 RC1 的新增交付承诺。
