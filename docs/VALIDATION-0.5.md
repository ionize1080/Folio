## 长任务实测

300 页测试为向合成 PDF **应用已有 OCR 结果**，不是识别 300 页的速度测试。

- 应用耗时：129.9 秒。
- 输出大小：17,761,542 字节，约 16.9 MiB。
- 测试进程峰值常驻内存：约 1,316.3 MiB（1.29 GiB），包含测试工具、生成、应用及独立渲染验证。
- 对每页分别验证可检索文字和原图像素，未抽样跳页。
- 在本次开发中，未释放字体句柄的实现一度观察到约 9 GiB 常驻内存；已补齐释放，并以同一套长测复验。

上述耗时与内存只代表该样本及测试环境。用户的扫描分辨率、页内容密度、模型、处理器和内存会影响结果，不能据此保证真实年鉴识别提速倍数。

## 运行包验证

使用重新下载并校验 SHA-256 的官方 Electron 44.3.0 Windows x64 ZIP 构建。已通过可执行文件架构、版本、图标、资源检查，284 个应用文件和 2,377 个原生文件与源码一致；压缩包完成后检查 CRC 并提供 SHA-256。

旧 0.4 基线包中 Folio.exe 的实际散列与其 BUILD-INFO 声明不一致，PE 节范围也超出文件长度，因此此次构建没有采用它的 Electron 可执行文件。构建脚本现会拒绝版本或 EXE 校验和不匹配的旧运行时。0.5 使用官方运行时重新构建；原生侧 101 个 PE 文件的节范围已检查。

## 复现入口

`npm test`；先运行 `tests/native-v4.py` 生成四页 OCR 扫描样本，再运行 `tests/ocr-jobs-v5.cjs` 和 `tests/ui-v5.cjs`。`tests/native-v5.py` 生成并验证 300 页样本。`tests/scheduler-v5.cjs` 模拟资源恢复，`tests/bridge-v5.cjs` 检查取消与重启，`tests/recovery-v5.cjs` 检查 IndexedDB 恢复。最后运行 `scripts/verify-package.mjs`。

完整原始报告随源码与运行包的 docs 目录附带；测试生成 PDF 不打入发布包。
