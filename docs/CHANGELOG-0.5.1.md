# Folio PDF Studio 0.5.1 修复说明

## 原因

用户报告的错误为 `No module named 'memory'`。Windows 内置 Python 的 `python312._pth` 只列出了运行时目录与依赖目录，没有包含 `worker.py` 所在的 native 目录。交付包中虽然存在 `memory.py`，Python 仍无法导入。

旧版在 OCR 推理完成后导入该模块以采集内存，异常被上层当作整页识别失败。因此可以看到进程持续占用 CPU，却没有成功页。内容检查及应用用到的同目录 `content.py` 也存在相同导入风险。这是交付包兼容性缺陷。

## 修复

- 原生服务启动时，将根据自身文件位置确定的 native 目录加入模块搜索路径，不依赖启动工作目录。
- 内存统计改为可降级的附加信息；采集失败返回 0 并写诊断日志，已完成的识别结果仍正常返回。
- OCR 窗口直接展示可复制的失败详情，首次失败自动展开；最多展示 30 页详情并提示其余失败数。
- 窗口标题、界面及应用版本统一为 0.5.1。此前标题硬编码为 0.4.0。

## 更新现有 0.5.0

1. 停止正在运行的 OCR，退出 Folio，确认程序已关闭。
2. 解压 `Folio-PDF-Studio-0.5.1-patch-from-0.5.0.zip`，将其中 resources 文件夹复制到原 Folio.exe 所在目录，合并文件夹并覆盖同名文件。请勿将原 resources 整体删除。
3. 启动 Folio.exe，窗口标题应显示 0.5.1。先重新识别 1–3 页，确认结果后再识别整批页面。

补丁仅适用于已有完整 0.5.0 运行目录。无需安装 Python、下载模型或修改系统环境变量。补丁不替换 Folio.exe，因此其 Windows 文件属性中的版本仍可能显示 0.5.0；应用窗口显示 0.5.1。若使用完整 0.5.1 运行包，解压到新目录运行即可，其 EXE 文件属性也为 0.5.1。

不需要手动清空所有 OCR 缓存。失败页可通过重新开始识别重试。此补丁不修改用户 PDF。

## 验证与边界

- 使用用户提供的《上海金融年鉴》第 4 页，在 Python `-I` 排除脚本目录的条件下，旧代码复现了完全相同的 `No module named 'memory'`。
- 修复后在上述隔离条件和无关工作目录中识别出 29 条文字，内容检查成功，写入文字层后用独立 PDF 库确认可提取文字。
- 主动阻断 memory 模块导入后，实际 OCR 仍输出 29 条文字，内存统计降级为 0。
- 30 项核心测试全部通过；浏览器测试确认失败详情无需悬停即可看到，窗口标题为 0.5.1。
- Windows 运行包进行文件、版本、原生模块及源码哈希静态检查。

这些测试在 Linux 完成；Python `-I` 用于复现模块搜索路径缺失条件，不等于真实 Windows 启动测试。仍需用户在实际 Windows 环境验证启动与 OCR。此次未重新执行几百页完整性能回归，不承诺性能提升。
